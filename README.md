# Спортивная драма

Для работы серверу нужны переменные окружения Render:

- `DATABASE_URL` — строка подключения к Neon.
- `ADMIN_PASSWORD` — пароль руководителя для раздела «Настройки». Задайте его в **Render → Web Service → Environment**; не добавляйте пароль в репозиторий.

После добавления `ADMIN_PASSWORD` Render перезапустит сервис. Руководитель открывает «Настройки» во всплывающем окне поверх текущей страницы, вводит пароль и получает доступ к параметрам игры, составу команды, челленджам и истории с откатом. Удаление участников находится в разделе «Состав команды» и требует сессии руководителя также на сервере. При закрытии окна приложение завершает сессию; при следующем открытии пароль требуется снова. Сессия на сервере истекает через 8 часов; кнопка «Выйти» завершает её раньше. Если пароль заменить в Render, старые сессии перестанут работать.

Курсы начисления шагов за оплату и кросс-сейл, челленджи и дополнительные действия общие для всех команд. При первом запуске общего набора сервер копирует их из текущего сохранения команды Фоменко в `department_rules`; последующие изменения через настройки любой команды обновляют этот набор. Новые команды загружают его перед первым сохранением. Если какое-то условие уже использовали в любой команде, его название и курс фиксируются для всего отдела; включать и выключать его можно. Прогресс игроков, история, название периода и награды за рубежи остаются отдельными для каждой команды.

В разделе «История» настроек руководитель выбирает команду из списка и видит только её записи. Откат сохраняется в выбранную команду.

Запись состояния новой команды впервые выполняет руководитель после входа. Последующие обычные игровые действия доступны без пароля; сервер отклоняет попытки изменить настройки, зачёты челленджей или прошлую историю без авторизации.

В настройках руководитель может вручную начислить от 1 до 10 000 монет выбранному менеджеру, указав причину. Начисление добавляется в кошелёк и журнал истории; откат записи отменяет его. Без авторизации сервер не принимает изменение ручных начислений.

В настройках руководитель может менять цены и названия наград, отмечать их как супер-призы, задавать общий лимит на отдел и добавлять новые позиции. Каталог магазина общий для одиннадцати команд и хранится в `department_shop`. По умолчанию сертификат 1 000 ₽, кино от босса, Day off и оплата у робота Алёши — супер-призы с лимитом 5 штук каждого на весь отдел. Один менеджер может получить приз повторно через кейс, пока есть общий остаток. Счётчики выдач хранятся в `super_prize_inventory` и не обнуляются при начале нового периода. При первом включении общего лимита для ранее ограниченных наград текущие неотменённые покупки учитываются в остатке; при превращении обычной награды в супер-приз её прежние обычные покупки не считаются. Снижение лимита ниже уже выданного показывает нулевой остаток. Индивидуальная гифка — обычная награда без ограничения по количеству.

Магазин продаёт кейс за 2 монетки. Сервер выбирает одну доступную награду случайно, одновременно списывает монетки и резервирует супер-приз; прокрутка в браузере показывает уже зафиксированный результат. Шансы видны рядом с составом кейса и пересчитываются при изменении магазина или окончании супер-приза. Для стандартного набора веса составляют 2400 для приза ценой 1 монетка, 1200 для цены 2, 600 для цены 3, 100 для супер-приза ценой 2, 50 для цены 4 и 20 для цены 7; реальные проценты нормализуются по доступным позициям. Кейс нельзя отменить после открытия, чтобы не получать бесплатные повторные попытки. Старые прямые покупки остаются в истории и сохраняют прежние правила возврата. Повтор запроса с тем же идентификатором открытия возвращает первоначальный результат без второго списания. Проверки: `node --test`.
